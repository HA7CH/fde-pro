## 一句话定位：土 FDE 的胜负手在"进得去现场 + 48h 拿下老板"

大厂线的护城河是企业约束层和面试语言；土线没有平台、没有品牌、没有销售帮你进场，**你自己就是销售 + 交付 + 售后**。所以土线的差异化能力全在 SKILL.md 尺子之外的这几件"脏活"上：**判客户（人和钱）→ 真下地调研 → 48h 交付一个点 + 一个面 → 用一套最小架构低成本落地。** 这四块正是本文四节。

## 一、接单前：先判"人"和"钱"（Echo 的商务前置）

土 FDE 最贵的资源不是流量，是**一个老板愿意让你进他公司、看他的数据、看他的员工怎么干活**——这本身门槛极高。所以接单前先判两件事：这个场值不值得进、这个老板付不付得出钱。

### 1. 获客三渠道 = 三种信任关系
FDE 获客的本质，是让企业**愿意放你进入现场**。三个渠道对应三种信任：
- **人脉（过去积累的信任）**：ToB 第一单几乎都靠身边已有信任。**别一上来就说"我帮你做 AI 转型"**，先问一个极简单的问题——"你们公司现在有没有什么流程特别烦、特别慢、特别依赖人工？"，找到一个具体问题先进现场。
- **自媒体（提前建立未来的信任）**：ToB 内容粉丝不多，但后台全是企业老板/从业者、询单精准。要讲**行业 + 你怎么进现场做出结果**，别只讲模型更新。
- **ha7ch 48h FDE Sprint（借社区和真实项目建立信任）**：没有写好的题目，先和老板聊目标、坐到一线员工旁看真实的微信群 / Excel / PDF / 业务系统，自己判断"哪一个问题真正值得在 48 小时内解决"，做一个小 MVP。

> 原话（口播，已还原 ToB/FDE/AI/ha7ch）：
> "ToB 其实最重要的不是流量，而是信任——一个老板他愿意让你进他的公司，看他的数据，看他的员工是怎么工作的，这本身就是一个门槛非常高的事情。"
> "这三个渠道本质对应的是三种信任关系：第一个是人脉，用过去积累的信任；第二个是自媒体，提前建立未来的信任；而我们的 FDE Sprint，就是借助社区和真实的项目来建立信任。"

### 2. 商务 call 四问（接到询单，先摸清客户在哪一层）
接到企业老板的商务电话，先用四个问题快速识客——**答完这四问，大部分 concern 就消掉了**：
1. **这事是不是一把手（CEO / 董事长）要做？** —— 不是一把手推动的 AI 项目，多半落不了地。
2. **公司有多少人天天看电脑？** —— 数字化人群规模，决定值不值得做、做多大。
3. **现在用不用飞书 / 钉钉？** —— 有没有现成的协同底座（后面 gateway 直接接它）。
4. **现有系统是订阅制还是买断？** —— 制造业大多是买断（金蝶 / 用友这类），决定你是插进去还是替换掉。

> 原话（口播）："第三个问题是你们现在是否有使用飞书和钉钉？" / "你刚才提到这些系统是订阅制还是说已经买断……其实大多数制造业都是买断的。" / "因为这四个问题已经解决了我很多的 concern。"

### 3. 筛选老板，也是 FDE 能力（判"钱"）
接单前先研究这个老板到底**有没有钱、能不能把尾款/工资付出来**，别干完活才发现老板没钱。选对老板本身就是一项 FDE 能力，不是接单后才想的事。
> 原话（口播 / 封面 OCR）："回到 FDE，我觉得就是选择对的老板，你要去研究一下这个老板。" / 封面："筛选老板 / 也是 FDE 能力。"

### 4. 进场前先补"先理解利益"（技术人尤其要补）
技术出身的人做 FDE，进场前先补一点管理咨询那套（《The McKinsey Way》），核心是**先搞懂各方利益关系，而不是一上来就谈技术**。老板要的、主管怕的、一线烦的往往不是一回事——先理解利益，才摸得到真需求。

## 二、进场调研：真下地 + 扛得住（Echo 的操作化 + 驻场软素质）

### 1. "不穿拖鞋"：调研不是会议室问需求，是沿业务走到看见问题
真实的 FDE 调研，**不是坐在会议室里问一句"你们有什么需求"**，而是沿着真实业务一路往下走——看进度、看展厅、看产线，顺着业务去供应商工厂看图纸怎么变成产品，直到**亲眼看见问题发生在哪里**。
> 原话（手写发布简述，最干净来源）：
> "一天跑完两家工厂，我越来越觉得，FDE 调研不是坐在会议室里问一句'你们有什么需求'。"
> "而是沿着真实业务一直往下走，直到亲眼看见问题发生在哪里。"
> "Ha7ch 最近也在筹备 48 小时 FDE Sprint：直接进入企业、梳理员工工作流，再做出一个能够被现场验证的原型。"

## 三、48h 交付什么：一个点 + 一个面（薄切片的现场纪律）

### 1. 抗枪：48h 交付不出"替代一个人"，交付"一个点 + 一个面"
48 小时内**不可能**交付一个端到端、完全替代一个人的系统。你要交付的是"一个点 + 一个面"：
- **面**：一份充分调研后的**企业 AI 提效方案**（覆盖到哪些环节、怎么落）。
- **点**：从调研对象里挑一个有亮点的做成**小 demo**，让一线员工真切感到"这东西确实能帮到我"、愿意动起来用 AI。
- 到现场要起到"**扛枪**"的作用——48h 的真实目标是**拿下老板**，让他愿意谈后面的合作，而不是交一个完美系统。

> 原话（口播，"扛枪"以口播正文为准；标题误写为"抗枪"）：
> "你是不可能交付一个端到端的东西，然后完全去代替一个人的，这是不可能的。"
> "让这个员工感觉这东西确实能帮到我，所以你要来到公司，你要起到扛枪的作用。"
> "那你在这个四十八小时内要做的事情，其实就是要拿下老板……让他愿意跟你商谈一下后面的合作计划。"
> —— `~/Documents/Lawted's-Video/小红书全量归档_2026-07-13/笔记/2026-07-16_6a5859b50000000013026b7f_FDE 要起到抗枪的作用/完整内容.md`

### 2. 标准方案之外，才是价值（海底捞 · 反纯标品）
用海底捞类比：你跟客户说的是**标准化方案**，但真正交付的是**标准之外的东西**。核心价值在服务（超出预期），否则你就和别的火锅没有任何区别。这是土 FDE 明确反纯标品 SaaS 的态度锚。
> 原话（口播）："第一，就是你跟别人说的是标准化的方案，但是你拿出的是这种（标准之外的）东西。" / "核心价值就在于这个服务，不然的话你就和别的火锅没有任何区别。" / "去他妈的 SaaS。"（封面："FDE 公司要 / 模仿海底捞"）
> —— `~/Documents/Lawted's-Video/小红书全量归档_2026-07-13/笔记/2026-07-19_6a5ce97b000000000f008df9_标准方案之外，才是价值/完整内容.md`

> **映射 SKILL.md**：这就是**满分尺子 + 薄切片**的 48h 落地版——"点"= 当场可验的薄切片让一线脱口而出"这能帮到我"；"面"= 领域正确的整体判断。"标准之外才是价值"= 护城河真相④（领域正确 + 端到端落地，不是某个标准功能）。**警惕**：把 48h 说成"上线整套系统替代 N 人"= 触发 R7（乱许诺）。

## 四、企业 AI 最小交付架构：token + harness + gateway

土 FDE 的 Delta 不需要重型工程，一套**最小架构**就能低成本端到端落地。这套架构本身也是卖给老板的方案。

### 1. 三件套：token（Claude）+ harness（Claude Code）+ gateway（飞书）
企业智能体可拆成三件套——**token 来自 Claude 订阅、harness 是 Claude Code、gateway 是飞书**；用 Claude Code 直接打包，token 走订阅、20 刀包圆，便宜。
> 原话（口播，已还原 Claude / Claude Code / gateway）："一共分为三个东西，一个是 token，一个是 harness，最后一个是 gateway。" / "这样的话二十刀就包圆了，比较便宜。"（关键帧 OCR："搭一套企业智能体 / 20 刀"）

### 2. 车队案例：One Source, Five Roles, No RAG
以 Claude Code 为基座，**不做任何 RAG**，直接用它 read / grep 的能力；CC Connect 把它接到飞书作连接层；按角色（车队经理 / 工程师 / 后勤）配不同 skill 和 prompt。"数据库"其实就是一个 GitHub 仓库里的 Markdown——文件解析成 Markdown / JSON 后 commit 进去，Claude 跑在老板放在新加坡的一台 Mac mini 上。

### 3. 跳过信息化：从 Excel 直接到 AI
很多工厂**没做信息化也照样生产**。别劝老板先花几百万上 ERP / PLM / MES / WMS——信息化 = 多一层规则，底层数据要先过这层才谈应用。**跳过它**，直接从业务员的 Excel 表格到 AI 应用。
> 原话（口播，已还原 AI/Excel/PLM 等）："很多工厂在现在这个阶段，他们没有信息化，但是也还在生产。" / "因为你做了信息化过之后，相当于你又多了一层规则。" / "我直接就是从那些业务人员的 Excel 表格，直接就到 AI 的运用那一个部分。"

### 4. WorkBuddy + Supabase 解 90%
卖给老板的方案就是 **WorkBuddy + Supabase**（或 WorkBuddy + 多维表格）——多维表格字段仍按原来 ERP/CRM 的思路设计，这套能解决 90% 企业的问题。48 小时直接给老板卖这个方案。
> 原话（关键帧 OCR 拼写干净 / 口播）："我现在觉得 WorkBuddy 加上 Supabase……可以解决 90% 企业的问题。" / "真的，以后你四十八小时，你直接给老板就卖这个方案。"

### 5. 数据安全：端侧一体机（打消老板最大顾虑，卡进"甜点区"）
推 WorkBuddy 时企业最担心的是**数据安全**。答案是一台**全国产化的端侧算力一体机**，装上 agent，放进保密场景（法务、政府秘书处、审计），本地处理机密合同 / 内部会议纪要 / 机密数据，**数据不上云**。硬件按配置 1–3 万，加 AI 技能约一台卖 10 万——正好落在**一个科室的预算就能 cover 的甜点区，不用走招投标**。（延伸：若 DeepSeek 出一台带 harness 的信创一体机，就成了"每个人一个数据完全合规的 DeepSeek 工作台"。）
> 原话（口播）："这个是一个端侧算力的一体机，全国产化的。" / "一个科室的预算就可以 cover 掉，不用再走招投标，是一个非常舒适的甜点。" / "内部的这种会议纪要，你不能传到云端去处理它，它一定要用这种方式。"

## 一句话总纲

土 FDE 没有平台替你兜底，所以赢在尺子之外的脏活：**接单前先判人和钱**（商务 call 四问 / 筛选老板 / 先理解利益），**进场真下地**（不穿拖鞋 + 肠胃扛得住），**48h 只交一个点 + 一个面**（扛枪、拿下老板，不假装替代人），**用 token + harness + gateway 最小架构低成本落地**（No RAG、跳过信息化、WorkBuddy + Supabase、端侧一体机保数据）。这四件事全都长在 SKILL.md 的 Echo + Delta 上——本文只是把它们从"是什么"翻译成"在一个真实现场怎么做出来"。
